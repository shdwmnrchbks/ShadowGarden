# Shadow Garden v2.5.0 — Motion & Continuity

Shadow Garden v2.5.0 completes the four-slice Motion & Continuity milestone. Motion remains progressive enhancement: it explains state changes and route continuity without becoming an owner of reading state, catalog state, Garden Keeper workflows, API requests, navigation, or persistence.

## Slice 1 — Motion foundation

- Shared press, fast, UI, layout, and page timing/easing tokens.
- Progressive View Transition helper with immediate fallback when unsupported.
- Shared restrained press feedback.
- Explicit `prefers-reduced-motion` contract.
- Architecture guards that keep motion outside application-state ownership.

## Slice 2 — Library continuity

- Main and Adult Library filtering, sorting, reading-state, pinned, and Grid/Compact changes reuse the canonical Library controller while adding visual continuity.
- Stable catalog-card transition identities allow surviving cards to move and resize instead of forcing whole-grid fades.
- Skeletons hand directly into hydrated cards without an intermediate blank state.
- Library → Series shared-cover continuity is available where browser support permits it.

## Slice 3 — Series + Reader continuity

- Series observes renderer-owned reading state and progress, then interpolates presentation between old and newly rendered values.
- Reader chrome, drawers, progress feedback, and viewer-ready presentation use the shared motion language without changing Reader session, flow, progress, settings, or auto-hide ownership.
- Same-origin Series ↔ Reader root continuity uses cross-document View Transitions where supported.

## Slice 4 — Garden Keeper + navigation continuity

- Garden Keeper now loads the shared motion foundation through its existing composition root.
- An observer-only Keeper motion workflow adds restrained dialog entrance, state feedback, busy/settled action feedback, manager refresh continuity, maintenance feedback, and upload-completion presentation.
- Keeper motion does not make `AdminClient` requests, open or close dialogs, mutate canonical upload/library state, or persist application data.
- Same-origin navigation receives a transient session-only `forward`, `backward`, or `lateral` presentation hint. Links and existing controllers still perform every route.
- The navigation drawer uses the shared timing/easing contract and reduced-motion-safe item choreography.
- Motion assets are explicitly `no-store` so versionless authored asset URLs do not retain stale choreography across deployments.

## Accessibility and performance

`prefers-reduced-motion: reduce` collapses optional motion to effectively immediate updates while preserving every functional state change and route. Motion favors browser View Transitions, CSS `transform`/`opacity`, native scrolling, and observer-based presentation feedback rather than JavaScript-driven inertia or continuous layout animation.

## Security and compatibility

No account or reading-state migration is required. Browser-local progress, bookmarks, Finished state, pinned state, and Reader/Library preferences retain their existing owners. The private B2 storage boundary, signed media tickets, Garden Pass/Turnstile, signed Keeper sessions, abuse controls, opaque book/cover identities, protected Range delivery, and public catalog redaction remain unchanged.

## Verification

The v2.5.0 GitHub release is eligible only after:

1. the exact `main` commit passes the complete Verify suite and production build;
2. Cloudflare production `/data/version.json` reports both version `2.5.0` and that exact commit;
3. Main Library, Adult Library, Series, Reader, and robots production smoke checks succeed; and
4. the verified v2 publisher confirms that `v2.5.0` does not already exist before creating the release.

See `docs/architecture/MOTION_SYSTEM.md` for the motion ownership contract and `docs/releases/v2.5-motion.md` for the four-slice milestone plan.
