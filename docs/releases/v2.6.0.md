# Shadow Garden v2.6.0 — Reliability & Real-Browser Testing

Shadow Garden v2.6.0 makes real browser behavior the final acceptance authority for high-risk Library, Series, Reader, and Garden Keeper flows. The existing deterministic unit, service, DOM, browser-contract, architecture, and security checks remain in place; v2.6 adds a bounded Playwright layer across Chromium, Firefox, WebKit, and mobile emulation instead of replacing those lower layers.

## Real-browser harness

- Add an isolated `tests/e2e/` Playwright workspace pinned to 1.62.1 with its own committed lockfile.
- Run Chromium, Firefox, and WebKit desktop projects plus Chromium Mobile and WebKit Mobile in CI.
- Build and serve the real production `dist/` output while intercepting only deterministic catalog, authorization, media, and external-service boundaries.
- Generate the Reader EPUB fixture before each run instead of committing binary test books. The fixture exercises protected `/book-access` acquisition, canonical `/media/shadow-garden/books/` delivery, HTTP Range responses, ordinary chapters, illustrations, visual-only pages, deliberately oversized image wrappers, large chapters, legacy-readable structures, and split-XHTML chapters.
- Retain trace, screenshot, video, HTML report, console, page-error, and failed-network diagnostics when a browser test fails.

## Public Library, Series, and reading lifecycle

- Make Main and Adult shelf isolation, search/filter/view state, Compact/Grid behavior, Back/Forward restoration, pinned navigation, suggestion rerolls, responsive navigation, reduced motion, and canonical first paint real-browser covered.
- Keep deterministic shell content in static HTML where it is knowable before hydration, including the Adult safety gate, Reader loading copy, and Garden Keeper shell styling/copy.
- Exercise the complete **Read → Continue → Finished → Read Again** lifecycle through the production Series and Reader actions, including exact resumed location, bookmark preservation, page-1 restart, and the final Unread state returning to Library.
- Harden cross-document View Transition handling so skipped transitions remain progressive enhancement and never become reading-state or navigation owners.
- Keep reading-suggestion rerolls motion-aware, reduced-motion-safe, and accessible when no alternate suggestion exists.

## Reader reliability

- Verify protected Reader startup, real EPUB.js rendition, Pages/Continuous flow switching, persisted progress/bookmarks, TOC navigation, next/previous controls, keyboard paging, desktop wheel ownership, mobile swipe policy, resize/orientation behavior, and image focus across the supported browser matrix.
- Renew protected book access after sleep/background-style visibility restoration without moving the live Reader location, while reusing comfortably-live cached tickets during ordinary tab switches.
- Keep Continuous vertical scrolling native: Reader page navigation does not install EPUB-document `touchmove` interception, and Continuous touch-action remains unclaimed by the Pages input owner.
- Harden Continuous manager teardown/scroll lifecycle against late callbacks and manager variants, and harden theme repair against EPUB nodes detached during rendition transitions.
- Keep image focus isolated from the live EPUB viewport. WebKit uses parent-owned image hit targets rather than enabling scripts inside publication documents.
- Modernize mobile Pages swipe handling with Pointer Events plus Touch Events fallback. Chromium proves the live synthetic gesture path; WebKit uses capability-aware navigation acceptance plus source-contract verification where Playwright cannot manufacture a trusted cross-frame swipe.
- Resolve issue #154: mobile Continuous artwork uses the full reading width, the seek rail is a thin transparent overlay, hidden chrome reveals only on tap/upward interaction rather than downward reading scroll, image focus activates reliably in one tap, paginated content clears the top chrome, controls meet a 44px minimum target, and browser zoom is allowed.
- Resolve issue #157: mobile Continuous uses the full viewport after chrome auto-hide, and chapter-title/active-TOC tracking correctly inherits the nearest navigation chapter across chapters split into multiple XHTML spine items.
- Resolve issue #160: while mobile Continuous chrome is visible, the progress rail and near-start thumb begin below the fixed top bar and return to the viewport top when chrome hides; Continuous artwork is also bounded by the EPUB viewport even when publication CSS places it inside an oversized fixed- or viewport-width wrapper.

## Garden Keeper reliability

- Verify the real locked → Turnstile/session-established → unlocked flow while mocking only external/service boundaries.
- Verify native Keeper dialogs remain keyboard-contained, Escape-operable, and restore focus even after manager rerenders replace the original opener node.
- Exercise Series editing and fan-translation metadata, volume translation overrides, upload preflight/completion/retry, Maintenance, Catalog History, Trash, and Abuse Watch presentation flows.
- Hold service responses during E2E to prove Series, translation, upload, History, Trash, and Abuse mutations cannot double-submit while busy.
- Preserve recoverable failure presentation: controls re-enable, failed upload items remain retryable, and handled service errors stay distinguishable from unexpected browser diagnostics.
- Keep the shared `AdminClient` and existing Keeper workflows as the only request/state owners; motion remains observer-only.

## Accessibility verification

- Add bounded automated accessibility scans for Library, Series, Reader chrome, and Garden Keeper.
- Verify keyboard-only critical flows, dialog/drawer focus restoration, visible focus, `prefers-reduced-motion`, forced colors, and increased contrast.
- Verify 200% and 400% equivalent zoom/reflow where applicable and audit mobile Reader/navigation touch targets.
- Allow normal browser pinch/zoom instead of constraining the Reader viewport.
- Document publication-owned EPUB accessibility separately from Shadow Garden chrome responsibilities in `docs/architecture/ACCESSIBILITY_TESTING.md`.

## Security and data compatibility

No server-side reading account, reading-data migration, or security-boundary change is required. Browser-local progress, bookmarks, Finished state, pinned state, Reader settings, Library preferences, and Adult acknowledgement retain their existing owners. Private Backblaze B2, opaque public identities, signed EPUB tickets, protected Range delivery, Turnstile/Garden Pass, signed Garden Keeper sessions, abuse controls, public catalog redaction, and the existing Pages Function service boundaries remain intact.

## Release verification

The v2.6.0 GitHub release is eligible only after all of the following are true for the exact release commit on `main`:

1. **Verify Shadow Garden** passes the complete repository/security/behavioral checks and production build;
2. **Real Browser E2E** passes the Chromium/Firefox/WebKit desktop plus Chromium/WebKit mobile matrix;
3. Cloudflare production `/data/version.json` reports version `2.6.0` and that exact commit;
4. Main Library, Adult Library, Series, Reader, and robots production smoke checks succeed; and
5. the v2 publisher confirms `v2.6.0` does not already exist before creating the GitHub release.

The reusable `.github/workflows/release-v2.yml` publisher enforces the exact-main browser gate, matching production deployment, public smoke, and final GitHub release creation. The milestone roadmap then advances to v2.7.0 Performance & Scale without weakening the v2.6 regression matrix.
