# v2.5 Motion Slice 4 — Keeper + Navigation

- Garden Keeper now consumes the shared motion foundation through its composition root while preserving every existing workflow owner.
- Keeper dialogs receive restrained entrance/backdrop choreography, dashboard and manager surfaces receive continuity feedback, and save/upload/maintenance state changes are observed rather than recalculated.
- Upload completion, Library refreshes, maintenance opening, state pills, and busy action buttons receive short lifecycle feedback without making API calls or persisting motion state.
- Shared motion now records a transient `sessionStorage` navigation-direction hint for same-origin links: forward, backward, or lateral. It never prevents the click or performs the route itself.
- The hidden Garden Keeper shortcut publishes a navigation-intent event immediately before its existing navigation call so the motion layer can preserve direction without owning that shortcut.
- The navigation drawer now uses the shared duration/easing tokens and restrained item entrance choreography.
- Motion assets are explicitly no-store in deployment headers so versionless authored asset URLs do not retain stale choreography across releases.
- Garden Keeper motion assets are registered in both architecture entrypoint manifests, and browser-contract tests permanently guard ownership, reduced-motion fallbacks, navigation non-interception, and deployment freshness.
- Final release reconciliation promotes `package.json` and the lockfile together to **2.5.0** and adds `docs/releases/v2.5.0.md` as the canonical release notes.
- The verified v2 publisher is no longer frozen to v2.0.0: it resolves the current v2 package version, requires matching release notes, skips an existing tag safely, waits for the exact version+commit in Cloudflare production, runs public smoke checks, and only then creates the GitHub release.
