# Shadow Garden v2.6.7 — Continuous Media Width Independence

Shadow Garden v2.6.7 fixes two Reader defects reported on desktop browsers, both affecting full-page images in Continuous mode once the reopened #160 text-width column work landed.

## Fixed — full-page images clipped by the text-width setting (desktop)

Two mechanisms reshaped the synthetic full-page image plates that the Visual Page Cache substitutes for standalone cover/illustration documents:

- **Landscape plates clipped sideways.** The Continuous theme caps the publication body at the text-width setting, but the plate stylesheet capped its image at the full canvas width in fixed pixels. The higher-specificity plate rule defeated the theme's `max-width:100%`, so the image box overflowed the narrowed body and its overflow guard cut it off sideways - visible whenever the text width was narrower than the reading canvas (desktop; on mobile the canvas is narrower than every legal text width, so the boxes coincided).
- **Portrait plates clipped vertically.** The plate's fixed one-viewport body plus the theme's `2.5em` vertical padding inset the content box without shrinking the plate, so the bottom of a portrait plate fell into the hidden overflow band. Short desktop landscape windows hit the cap far more often than tall mobile portrait viewports, which is why mobile did not show it.

The plate stylesheet now re-asserts its exact one-canvas geometry through `data-sg-synthetic-visual` anchored rules that outrank any theme rule in both cascade orders, so no text-width, padding, or margin rule can reshape a full-page image. Paginated mode keeps its dedicated inline-style frame controller and is unaffected.

## Changed — Continuous artwork is independent of the text-width setting

The text-width setting now shapes prose only. In Continuous mode:

- `figure`/`picture` wrappers and media-only block containers expand to the full reading canvas (100vw inside the EPUB iframe) with symmetric negative margins that re-center them - a box wider than its containing block would otherwise stick out solely to the right and be clipped. Every expanded box is capped at exactly 100vw, so the canvas boundary still excludes the seek rail (#160 containment holds at any text width).
- The prose-column body no longer carries its own horizontal overflow clip: that guard clipped the legitimate bleed at the text-width edge. Containment remains owned by the canvas boundaries - the iframe viewport, the root `overflow-x` guard, and the `.epub-container`/`.viewer` clipping.
- epub.js's default `adjustImages` hook caps img/svg at 95% of a pre-theme body height - a column-pagination helper with no meaning in a scrolling canvas. Continuous mode releases that cap so portrait artwork renders at its true aspect; Paginated keeps it because a page really cannot overflow vertically.
- Text containers, prose insets, and mixed-content wrappers keep the text-width cap; engines without `:has()` keep the previous contained behavior for media-only divs (feature-detected).

## Regression coverage

New real-browser E2E (`continuous-media-width.spec.mjs`) renders a dedicated fixture with a 2400×1350 landscape plate, a 1350×2400 portrait plate, and the same shapes inline inside prose, then asserts on desktop Continuous mode that no image is clipped left/right/top/bottom against the canvas, that the plates are the synthetic one-viewport pages, that prose follows the text-width setting while every image width stays identical when the setting moves 760→1050, and that containment bounds still hold.

The complete v2.6 Chromium, Firefox, WebKit, Chromium Mobile, and WebKit Mobile regression matrix remains required, together with the reusable v2 publisher production gates.
