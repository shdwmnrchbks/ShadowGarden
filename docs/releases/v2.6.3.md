# Shadow Garden v2.6.3 — Continuous Media Containment Hardening

Shadow Garden v2.6.3 is a follow-up to the v2.6.1/v2.6.2 hotfixes for the reopened issue #160 item: real publications still clipped artwork at the right edge in Continuous mode even though width caps and rail-gutter reservations were already in place.

## Root cause

CSS resolves used widths as `max(min-width, min(width, max-width))`, so **a single publication rule such as `body{min-width:600px}` or `.page{min-width:900px}` overrides every `max-width` cap outright** and recreates an oversized canvas. The v2.6.2 clip boundary then sat at the wide canvas's own edge — beyond the reserved seek-rail gutter — so the artwork still ran underneath the transparent rail before being clipped. Real converted EPUBs carry these rules frequently.

## Fixed

- Reset `min-width` to `0` on the publication root (`html`, `body`) in Continuous mode, and add the same reset alongside the existing caps for every common wrapper (`div`, `section`, `article`, `aside`, `main`, `table`, `td`, `th`) plus `figure`/`picture`. A minimum no longer wins over containment.
- Render replaced media (`img`, `svg`, `video`, `canvas`, `object`, `embed`) statically and untransformed in Continuous mode: `position:absolute/fixed` anchors artwork against the iframe viewport where body padding cannot reserve the rail gutter, and rightward transforms can slide otherwise-valid media into that zone regardless of widths. Text-level decorations elsewhere are untouched.
- The generated Reader EPUB fixture gains a third oversized shape whose wrapper forces `min-width: 900px`; the mobile real-browser regression now requires all three shapes (figure-wrapped, bare-div-wrapped, min-width-canvas) to end at or left of the fixed Continuous seek rail.

The complete v2.6 Chromium, Firefox, WebKit, Chromium Mobile, and WebKit Mobile regression matrix remains required, together with the reusable v2 publisher production gates.
