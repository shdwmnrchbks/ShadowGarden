# Shadow Garden v2.11.0 — Engineering Audit, Refactor & Optimization

Shadow Garden v2.11.0 completes an audit-first engineering-health cycle across the repository, Reader, Library/Series domain, Garden Keeper, Pages Functions, CSS/accessibility, build/test tooling, and current documentation. The release deliberately does not add a new product surface or perform a framework rewrite. Changes were accepted only where measurements demonstrated a concrete correctness, ownership, lifecycle, security, verification, or realistic-scale performance problem.

## Repository and ownership cleanup

The repository now has mechanically checked browser and Pages Functions reachability, with demonstrated dead or obsolete owners removed rather than preserved as compatibility debt. The disconnected top-level reading-state facade, forwarding-only R6 compatibility facades, stale authored cache-version ownership, obsolete R-series policy executables, and later release-era standalone policy snapshots remain retired behind permanent guards.

Historical release, security, and architecture records remain historical evidence; they are not executable policy and are not rewritten merely because current ownership moved on.

## Reader long-session reliability

The Reader audit used a deterministic 6,315,313-byte EPUB with 18 spine chapters × 72 semantic passages and repeated Pages ↔ Continuous switching, viewport changes, Page Map supersession, search/TOC/navigation, resume/ticket behavior, and sustained Continuous traversal.

Targeted fixes corrected protected Page Map source ownership, cancellation and teardown of superseded hidden map sandboxes, EPUB.js 0.3.93 manager/listener/hook cleanup, and release of trimmed Continuous section caches. The final repeated-flow drain was approximately **+2.31 MiB heap / +702 Nodes / +4 Documents / +14 listeners**. Sustained Continuous traversal returned trimmed documents to zero retained Documents, +44 Nodes, zero retained listeners, and about +0.68 MiB heap while trimming transient 18 views/iframes back to five.

Those measurements did not justify Reader module consolidation, Page Map startup deferral, a new virtualization/buffering architecture, or a runner-sensitive heap ceiling. The existing Reader responsibility split remains canonical.

## Library, Series, and browser-local domain

A deterministic 300-series / 1,950-volume workload exposed repeated browser-local reading-state evaluation rather than a rendering-architecture problem. Reusing already-materialized volume state and removing unconditional Finished-state evaluation when no reading-status filter is active reduced localStorage reads from **121,905 to 14,211 during hydration (−88.3%)** and from **314,387 to 11,645 across the measured interaction workload (−96.3%)**.

Library and Series startup each retain one canonical catalog request, ordinary later loads remain fresh, and active-filter / Recent “View all” actions keep one canonical render owner. No virtualization framework, new persistence layer, or catalog-cache architecture was added.

## Garden Keeper runtime ownership

Garden Keeper retains one protected AdminClient and its existing workflow boundaries. Maintenance dialog hydration now performs one canonical `GET /admin-api/maintenance` instead of three identical requests across Maintenance, History, and Trash. Trash restore/purge reuses returned maintenance state without an immediate follow-up GET, while external invalidation still causes one fresh load.

Normal upload preflight now reuses the already-materialized Library snapshot from Keeper unlock instead of issuing a duplicate Library GET. The missing-snapshot/startup-race path still performs exactly one safe fallback request. Recovery-sensitive ordering, sequential B2 checks, one-at-a-time cover optimization, and ordered multi-EPUB upload remain unchanged because the audit did not demonstrate a bottleneck that justified speculative parallelization.

## Pages Functions, security, and storage

Read-only authenticated Library, Series Banner, Maintenance, and Recovery paths no longer require B2 write credentials. Storage transport chooses credentials lazily by HTTP method: GET/HEAD use read credentials; mutations require write credentials and never fall back to read credentials.

The live Functions graph remains **15 thin route roots → all 38 Functions sources**. Nine implementation-only unconsumed service exports were made private; three deliberate upload-validation policy seams remain public with direct security regression coverage. Normal Verify now owns the complete Functions security contracts and service regression layer, with 47 service tests at the Audit G closeout.

Private B2, signed media, opaque IDs, Keeper sessions, cooldowns, catalog redaction, recovery retention/anchor protections, and browser-local Reader history remain unchanged.

## CSS, motion, and accessibility

The audit measured **36 authored stylesheets / 2,254 selectors** and removed only selectors/tokens with concrete dead-owner evidence. Static cleanup converged to **zero literal unreferenced class candidates and zero unused authored custom properties**. Remaining specificity and `!important` pressure is concentrated in deliberate late-loaded workflow/theme/layout layers rather than evidence of a stylesheet-architecture failure.

Existing keyboard/focus restoration, reduced-motion, forced-colors, increased-contrast, zoom/reflow, browser zoom, and labelled mobile-target checks remain authoritative. No broad CSS consolidation or separate accessibility framework was introduced.

## Build, dependencies, tests, and tooling

Seven stale release-era standalone executables were retired, while still-useful M5–M8 security behavior was migrated into active service regressions. The current site-voice/destructive-warning guard now runs in normal checks. Verify and Baseline Health no longer repeat an identical repository check before the already-validated production build, removing roughly four seconds of duplicate deterministic work in the measured Audit G candidate without dropping a gate.

Shadow Garden retains Node 22, npm 10.9.8, committed root and isolated E2E lockfiles, the native no-bundler copy/stamp build, static Playwright preview, review-driven dependency maintenance, EPUB.js lifecycle revision guard, local B2 tooling, and the existing exact-main release publisher.

## Documentation and release convergence

Authoritative current roadmap, architecture, test, build, maintenance, dependency, audit, and release-status documentation has been reconciled with the accepted A–H implementation. Documentation freshness checks protect current version ownership, package-manager policy, retired executable claims, CSS audit ownership, build/check ownership, and final audit evidence while deliberately excluding immutable historical records from current-state rewriting.

Audits C–H were assembled onto the already-merged A/B `main` history through PR #231. The assembled mainline commit was independently reverified with Verify, Cloudflare Pages, Chromium desktop/mobile, Firefox desktop, and WebKit desktop/mobile before this formal release cut.

The formal release remains governed by the reusable v2 publisher: the exact release commit must pass Verify and the complete main-push Real Browser E2E matrix, Cloudflare production must report **v2.11.0** at that exact commit, public production smoke checks must succeed, and only then may the GitHub `v2.11.0` release be created.
