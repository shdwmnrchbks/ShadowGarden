# Shadow Garden v2.8.0 — Reader Experience

Shadow Garden v2.8.0 completes the Reader Experience milestone. It improves the reading surface used for long sessions while preserving the architecture and persistence contracts established by the v2 reliability work: Page Map, progress, bookmarks, protected-book access, and Pages/Continuous input ownership remain canonical.

## Focused typography and clearer progress

Reader typography now offers four intentional choices: publication-owned **Default**, **Sans** with PT Sans, **Serif** with Literata, and **Sans-Serif** with Inter. Legacy browser-local font preferences migrate safely without changing font size, line height, text width, flow, or other Reader settings.

Pages mode now presents canonical device page, volume percentage, and chapter context together. Continuous mirrors the same owner through its seek rail and accessibility text rather than introducing a second progress calculation.

## Long-book navigation and search

The Contents drawer can filter in place while preserving its collapse state. A **Current** action clears filtering, reveals the live chapter, and restores focus without moving the rendition.

The same Contents surface now owns whole-book text search. Ctrl/Cmd+F opens that unified search, Contents matches remain first, and book text is scanned sequentially through the canonical EPUB.js spine. Results are CFI-backed and open through the existing Reader navigation path. Searches require three characters, are cancellable, unload scanned sections, and stop at 100 results.

## Footnotes and resume recovery

Explicit EPUB noterefs now open sanitized Reader-owned footnote/endnote popups without moving the live passage, including same-document footnotes and cross-document endnotes.

Resume handling is hardened across reloads, orientation and viewport changes, backgrounding, BFCache/pageshow, and long idle periods. Protected access renewal is serialized before touching a long-suspended rendition. Layout-changing recovery prefers the semantic reading CFI, while unchanged-layout Continuous recovery preserves the same semantic content block at the same viewport-relative position when possible.

## EPUB compatibility and graceful failure

The Reader now has deterministic fixtures for a common imperfect EPUB that omits title/navigation conveniences and for an intentionally corrupt package. A stale saved CFI gets one bounded fallback to first readable content; genuine first-content failures are never masked.

Unrecoverable startup failures stay inside Reader-owned chrome with sanitized, actionable guidance, **Try again**, and a return action. Raw parser messages are not exposed to readers. Definitive invalid ZIP/package failures discovered by visual-page preflight are promoted to the same graceful startup surface instead of leaving the Reader indefinitely preparing the book.

## Reliability contract

The completed milestone is covered by the permanent real-browser matrix across Chromium desktop, Firefox desktop, WebKit desktop, Chromium Mobile, and WebKit Mobile where technically meaningful. Pages and Continuous retain separate input ownership, Page Map/progress/bookmarks remain browser-local and backward-compatible, and no live EPUB pinch/pan owner or Continuous touch interception is reintroduced.

The reusable v2 publisher still requires the exact release commit to pass Verify and Real Browser E2E, match Cloudflare production version/commit metadata, and pass public production smoke before the GitHub release is created.
